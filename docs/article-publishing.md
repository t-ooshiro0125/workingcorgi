# 記事下書きの整理と投稿準備

`src/content/drafts/` のドラフトを記事化、レビュー、投稿準備する際の手順。

## 基本方針

- 対象のドラフトだけを変更し、既存の変更は保持する。
- 記事の体験や意図を残し、重複、曖昧な表現、不要な脱線を整理する。
- 読みやすく簡潔な構成にし、必要な見出し、具体例、注意点だけを追加する。
- 外部リンクや変更されうる技術仕様は、公開前に一次情報または公式ドキュメントで確認する。
- 禁止: GitHub Discussions へ投稿しない。
- 禁止: Git のインデックスを操作しない。

## 記事化とレビュー

1. 対象のドラフト、執筆規約、投稿フォームを確認する。
2. 内容を記事として整理し、事実関係とリンク先を確認する。
3. 正確さ、読みやすさ、構成、投稿形式の観点でレビューする。
4. 指摘がなくなるまで修正とレビューを繰り返す。
5. 変更内容に応じて、`npm run format:check`、`npm run lint`、`npm test`、`npm run build` を実行する。

## 投稿準備

記事化または投稿準備を依頼された場合は、ドラフトの先頭に次の項目を用意する。

```md
### タイトル

### 概要

### 公開日

### URL スラッグ

### カテゴリ

### 本文
```

### 投稿形式

- タイトルは GitHub Discussions のタイトル欄に使用する。
- 概要、公開日、URL スラッグ、カテゴリ、本文は Articles の対応するフォーム欄に使用する。
- 公開日は投稿時点の日付を `YYYY-MM-DD` 形式で設定する。
- URL スラッグは英小文字、数字、ハイフンだけを使用する。
- 禁止: 公開後に URL スラッグを変更しない。
- カテゴリは `tech`、`note`、`devlog` から記事に合うものを選ぶ。
